# LatticePricer272 — Accuracy versus Computational Cost (v1)

## Scientific question

For a fixed vanilla European contract and a given compute budget, which lattice
provides the lowest **absolute pricing error**? How does the answer depend on
moneyness, lattice depth and node allocation strategy?

This experiment complements previous convergence and runtime benchmarks. It
**does not** replace them and **does not** modify any module in `src/`.

## Financial scope (Phase 1)

- Market: `S0=100`, `r=2%` continuously compounded, `sigma=20%`, `T=1` year.
- European calls **and** puts, `K` in `{80,100,120}`; no cash dividends.
- Black–Scholes is the analytical price reference, using our `BlackScholesPricer`.
- Time steps: `N` in `{20,40,60,100,150,200,300}`.
- Four methods: `BinomialTree`, `TrinomialTree(pruning_threshold=0)`,
  `TrinomialTree(pruning_threshold=1e-18)`, and
  `AllocationPrunedTrinomialTree(pruning_threshold=1e-18)`.
- All four use the same **RecursivePricer**. This isolates the lattice
  construction/pruning choice from a change of pricing algorithm.
- No Hybrid in Phase 1: absent dividends, it executes binomial transitions.
  We will reintroduce it in the discrete-dividend phase.

## Definitions

For contract `c`, model `m` and depth `N`:

- Error in euros: `e(m,N,c) = abs(V_lattice(m,N,c) - V_BS(c))`.
- Relative error: `e / V_BS` (when `V_BS > 0`).
- End-to-end runtime: constructor + `tree.build()` + recursive backward
  option pricing; **not** just the pricing traversal.
- One untimed warmup precedes each model/contract/N configuration.
- Five fresh-trees runs per point by default; **median** recorded.
- Explicit `gc.collect()` occurs *before* the clock, never inside it.
  Automatic Python garbage collection is left enabled; it may still occur
  during a measurement.
- Runtime excludes file output, plotting and `tracemalloc` overhead.
- Raw runtime samples are exported for auditing. Clock uses
  `time.perf_counter_ns()`.
- Allocated nodes are actual `allocated_node_count` for optimized trinomial.
  For no-dividend classical binomial and full-width trinomial we use the exact
  known structural counts `(N+1)(N+2)/2` and `(N+1)^2` respectively.
  Branch pruning does not remove allocated nodes.

## Outputs

Generated by the **full** run:

- `results/data/accuracy_cost_benchmark.csv`: full aggregated grid.
- `results/data/accuracy_cost_timings_raw.csv`: individual timed repetitions.
- `results/data/accuracy_cost_targets.csv`: fastest *sampled* depth per
  model/contract meeting each absolute-error threshold.
- `results/accuracy_cost_summary.txt`: settings, environment, caveats,
  ATM Pareto frontier and reached targets.
- `results/figures/accuracy_cost_runtime_call_K80.png`
- `results/figures/accuracy_cost_runtime_call_K100.png`
- `results/figures/accuracy_cost_runtime_call_K120.png`
- `results/figures/accuracy_cost_nodes_atm_call.png`
- `results/figures/accuracy_cost_steps_atm_call.png`
- `results/figures/accuracy_cost_pareto_atm_call.png`

**Pareto frontier:** a measured point is non-dominated if there exists no
other measured point with both a runtime no longer and an error no larger,
with at least one strict improvement. The frontier depends on the hardware,
current load, chosen `N`, and contract. It is not a continuous theoretical
frontier.

**Exact zero errors:** cannot be drawn on a logarithmic ordinate; they are
left out of log plots, not replaced by arbitrary epsilons, and retained as
zero in the CSV. `N`-induced convergence oscillations may cause curves to
zigzag; do not fit asymptotic powers to a handful of such points.

## Running on the fixed PC (Git Bash, from repository root)

```bash
python -m pytest tests/test_accuracy_vs_cost.py -q
python -m pytest -q
python -m experiments.accuracy_vs_cost --quick
python -m experiments.accuracy_vs_cost
```

The `--quick` run is restricted to the ATM European call at `N=20,40` and
writes into `results/accuracy_cost_quick/`; it **does not** overwrite the
full results. `--repeats 7` can be used for additional timing repetitions, but
runtimes across runs with different settings should not be merged.

### Review before any commit

1. Inspect test output and `results/accuracy_cost_summary.txt`.
2. Check that all configurations succeeded and that raw prices are stable.
3. Check sampling noise (`min_runtime_seconds` vs `max_runtime_seconds`).
4. Review all figures and CSVs for consistency.
5. Only then stage the useful script, tests, protocol, tables, figures and
   summary; no automatic commit or push.

## Interpretation limits and later extensions

- Prices are judged against Black–Scholes **only** because this phase has
  European vanilla options and no discrete cash dividend.
- A small error at one `N` need not imply superior asymptotic convergence:
  oscillation/cancellation can produce accidental minima.
- Median wall-clock time is machine- and load-dependent. Results from one
  PC are comparative evidence, not universal performance rankings.
- Timing includes tree construction, so pricing algorithms are held fixed.
- Phase 2 will use an independent *numerically converged* price reference
  for cash dividends/American exercise, with explicit uncertainty analysis.
- The professor's `Average option value by dates` and
  `Exercise probability by dates` experiments remain on the roadmap **before
  Streamlit**, after receiving their official slides.
